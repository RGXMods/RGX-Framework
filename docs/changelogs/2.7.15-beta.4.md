# RGX-Framework v2.7.15-beta.4

Beta candidate; stable remains v2.7.14. This source snapshot is not evidence of
publication or new in-game compatibility/safety acceptance.

## Changes

- Move declarative tab composition from core into a private UI-options
  compositor. Core keeps declaration resolution, storage and lifecycle; tabs
  are still built lazily through the existing scroll/column/flow/control
  factories with unchanged forms and callbacks.
- Enforce one defining file per `RGX.API` name: `core/compat.lua` owns the
  normalized implementations, `core/compat_api.lua` only adds names it does
  not define, and `tools/ci/api-ownership-check.mjs` guards the XML load list
  alongside the existing compat-loader check.
- Add the interface-style registry. `Design.STYLES` offers four named styles —
  `framework` (default), `retail`, `classic`, `forever` — each owning a corner
  treatment (`rounded` or `square`) plus a structural palette (surface,
  background, panelAlt, text, subtext, label, success, warning, error, border,
  hover, track). `Design:SetStyle(name)` applies a style — unknown names are
  rejected with `false` and never mutate the shared defaults — and
  `Design:GetStyle()` returns the current one. Primary/accent color presets
  stay independent of the applied style. The choice persists in
  `RGXFrameworkDB.style` and is re-applied at login; the settings panel adds
  an interface-style selector. As with the corner selector, styles take
  effect on UI built after the call and already-open windows re-skin on
  reload; retail/classic/forever palettes are starting points for in-game
  tuning. See `docs/THEMING.md` "Interface Styles".

Package: `RGX-Framework-v2.7.15-beta.4.zip`, 109 runtime files, plus
`release.json` automation metadata. Tooling and reference caches stay excluded.
