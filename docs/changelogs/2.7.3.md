# RGX-Framework 2.7.3

Released 2026-08-22.

## Protected-Action Hotfix (Tainted Event Registration)

Classic Era smoke testing surfaced `ADDON_ACTION_FORBIDDEN` raised from the
v2.7.2 lifecycle flush: `Frame:RegisterEvent` was being called synchronously at
the tail of `RGX:FireEvent()` while still unwinding Blizzard's event dispatch
stack. Modern clients can reject that call path even outside combat lockdown,
and `pcall` neither suppresses the protection report nor proves registration.

- Native `Frame:RegisterEvent` for deferred queue entries now runs only from an
  anonymous next-frame `OnUpdate` driver — never while unwinding an event
  dispatch, a timer dispatch, combat lockdown, unit combat, or a pet battle.
- The driver stays armed while pending registrations exist and disarms itself
  when the queue is empty. The `FireEvent` and timer-dispatch tails no longer
  touch the native frame API at all.
- Registration success is verified with `frame:IsEventRegistered()` when the
  client provides it. Known-invalid events are dropped immediately, and
  repeatedly rejected registrations are dropped after a bounded attempt cap —
  no infinite retry loops.
- The 2.7.2 deferral guarantee is preserved: handlers registered inside event
  or timer callbacks still become real native registrations, just one clean
  frame later.

## Retail CLEU gate

Retail 12.x rejects addon registration of `COMBAT_LOG_EVENT_UNFILTERED`.
`RGXCombat` no longer requests it on Retail, and the new explicit
`combatLogEvent` capability (true for Classic Era, TBC, Wrath/Titan, Cataclysm,
Mists) is flavor-gated rather than inferred from event validation. Combat
state, health/resource thresholds, target/proc/encounter/PvP callbacks keep
working on Retail; the payload-dependent callbacks (`OnKill`, `OnCrit`,
`OnCritHeal`, `OnPlayerDamaged`, `OnPlayerHealed`) degrade to non-firing, and
consumers can detect that via `RGXCombat:HasCombatLogEvents()`.

## Verification

- Event-lifecycle suite extended from 35 to 66 Lua 5.1 checks: dispatch-time
  queueing, no dispatch-stack native attempts, next-frame driver flush, nested
  dispatch single-attempt, timer deferral, combat hold and release, removal
  before flush, silent protection denials (bounded), C-API errors (bounded),
  and unsupported-event non-retry.
- Declarative-timer runtime coverage remains at 166 checks; restricted-aura
  boundary coverage remains at 86 checks.
- Six-flavor mocks now assert `combatLogEvent` per flavor; syntax, schema,
  flavor, package boundary, and docs checks remain green.
