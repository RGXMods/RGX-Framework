## v1.9.0

### Database — NewDatabase API
- **`RGX:NewDatabase(name, defaults, opts)`** — metamethod-based profile access
  - `db.key` reads from active profile, falls back to defaults at read time
  - `db.key = v` writes to active profile
  - `db.global` returns cross-character storage table
  - Profile CRUD: `CreateProfile`, `LoadProfile`, `DeleteProfile`, `RenameProfile`, `CopyProfile`
  - `OnProfileChanged(fn)`, `ResetProfile`, `GetProfiles`, `GetActiveProfile`
- Single `DB` metatable replaces dual `DBHandle`/`NewDBMeta` split
- `RGX:OpenDB` is now a 4-line wrapper around `RGX:NewDatabase` — backward compatible
- Step-by-step factory: init global → build proxy → merge defaults → ensure Default → pick active → fire callback

### Events — Combat Lockdown Safety
- Removed `pcall(frame.RegisterEvent, frame, event)` — raw C function reference through `pcall` triggers taint during combat
- Replaced with `pcall(function() ... end)` anonymous Lua closure — traceable call chain, no taint
- `RGXCombat` returned to dormant status: `RegisterEvent` is fundamentally blocked on addon frames during loading screen into combat zones (battleground, arena, world PvP)

### Roadmap
- Added RGX-Mod phased dependency table with framework API readiness tracking

### Misc
- Helper renames: `deepMerge` → `MergeDefaults`, `getByPath` → `GetPath`, `setByPath` → `SetPath`
- `NotifySwitch` guard prevents re-entrant callback chains
- `InCombatLockdown` guard in `RGXCombat` init with `PLAYER_REGEN_ENABLED` retry fallback
