# RGX-Framework 2.7.0

## Declarative Named Repeating Timers

- Shipped `every = { name = { seconds, handler } }` as a complete declarative
  vertical slice. Declarative `on` remains Tier 4.
- Validates printable names containing a non-space character, exact two-item
  tuples, finite positive intervals, and function handlers before registering
  the addon, slash commands, events, or timers.
- Binds timers after the matching consumer `ADDON_LOADED`, once its database,
  options panel, and minimap button are ready. The first call occurs after one
  complete interval.
- Calls handlers as `handler(addon, timer)` and supports self-cancellation with
  `addon:CancelTimer(timer)`.
- Adds owner/name metadata and stable `AddonName:every:name` labels. Timers in
  one declaration that become due together dispatch in lexical name order.
- Keeps failures isolated: one timer error is labeled and reported without
  preventing unrelated due timers from running.
- Rejects duplicate addon declarations before any resources can be replaced or
  leaked.

## Contract And Verification

- Promoted `every` to `x-rgx-ships: today` in the canonical schema while keeping
  `on` at `tier4`.
- Added 14 schema behavior vectors, strict non-finite-number rejection, MCP
  validation/generation, deterministic and safely quoted generated timer names,
  and RGX-Hello E2E coverage.
- Added a real Lua 5.1 runtime harness with 166 checks for validation, lifecycle,
  ordering, metadata, self-cancellation, duplicate rejection, and failure
  isolation.
