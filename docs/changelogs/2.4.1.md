## v2.4.1 - 2026-07-03

**Found by actually using `tools/rgx-mcp` to build a real addon**, per the "build API/MCP/Framework/Hello/test in tandem" direction — a new end-to-end test (`tools/rgx-mcp/test/test-rgx-hello.mjs`) drives the real MCP server, over the real MCP client SDK, and points it at the real RGX-Hello repo instead of synthetic fixtures. It immediately surfaced a real, silent bug and a real generator gap.

**Fixed: declarative slider `suffix` was silently dropped.**

`{ slider = "volume", suffix = "%" }` in an `RGXAddon` options table has always been valid Lua and produced no error — but the options-table-to-UI mapper in `core/core.lua` only ever forwarded `key`, `label`, `min`, `max`, and `step` to `UI:CreateSlider`. `suffix` was silently discarded. Every addon using it (including RGX-Hello's own Volume slider, shipped since v1.0.0) rendered the slider with no "%" indicator despite the code clearly intending one. The imperative `UI:CreateSlider` call already supported `suffix` correctly — only the declarative table path was missing it.

Also fixed: `schemas/rgx-addon.schema.json`'s `sliderControl` definition didn't allow `suffix` either, so `rgx_validate_addon` rejected the same key as invalid even though it was real, shipped, silently-broken-but-intended functionality. Both are now fixed together — the schema allows it, and the runtime honors it.

**Fixed: `rgx_generate_addon`'s hyphenated-name blind spot.**

For an addon named e.g. "RGX-Hello", the generator defaulted its SavedVariables hint to `${name}DB` = `RGX-HelloDB` (hyphen intact) with no way to override it. RGX-Hello's own hand-written `core.lua` ships `dbName = "RGXHelloDB"` (hyphen stripped) specifically to avoid this. The generator now strips non-identifier characters from the auto-derived default and accepts an explicit `dbName` override, plus `label`/`suffix` passthrough on generated sliders.

**New: `tools/rgx-mcp/test/test-rgx-hello.mjs`.** Generates a spec matching RGX-Hello, validates its actual opts table, and audits its actual Lua files — all against the real, currently-shipped RGX-Hello repo. Run it with `node test/test-rgx-hello.mjs /path/to/RGX-Hello`.
